# ANTIGRAVITY UNIVERSAL VISUAL INTELLIGENCE SYSTEM

## PURPOSE

Every project developed, modified, upgraded, redesigned, or maintained
through Antigravity must have access to a production-quality AI visual
generation, enhancement, inspection, and optimization workflow.

This standard applies to:

- New projects
- Existing projects
- Websites
- Web applications
- Mobile applications
- SaaS products
- Dashboards
- Games
- Marketing sites
- E-commerce
- Enterprise applications
- Landing pages
- Portals
- Internal applications
- Prototypes
- Design systems
- Projects containing existing images
- Projects containing existing videos
- Projects containing low-quality, outdated, or inconsistent media

The project technology stack does not change this requirement.


==================================================
1. VISUAL TASK DETECTION
==================================================

Before implementing a visual feature, inspect the project.

Identify:

- Existing images
- Existing videos
- Existing illustrations
- Existing icons
- Existing logos
- Existing 3D assets
- Existing animations
- Existing backgrounds
- Existing hero media
- Existing thumbnails
- Existing avatars
- Existing product photography
- Existing marketing media
- Existing generated assets
- Existing stock assets
- Existing placeholders

Determine whether each visual should be:

- CREATE
- ENHANCE
- EDIT
- RESTORE
- UPSCALE
- ANIMATE
- REPLACE
- RETAIN


==================================================
2. NEW IMAGE GENERATION
==================================================

When a visual does not exist and needs to be created:

Use the highest-quality image-generation capability available
through the project's configured AI providers.

The system should prioritize:

- Photorealism when appropriate
- High visual fidelity
- Strong composition
- Correct anatomy
- Accurate perspective
- Appropriate lighting
- Realistic materials
- Professional art direction
- Brand consistency
- Correct aspect ratio
- Correct resolution

Never create a low-quality visual merely to satisfy the requirement.


==================================================
3. EXISTING IMAGE ENHANCEMENT
==================================================

If the project already contains an image, DO NOT automatically replace it.

First inspect the image.

Determine whether it can be improved through:

- Resolution enhancement
- Upscaling
- Sharpening
- Noise reduction
- Artifact removal
- Lighting correction
- Color correction
- Contrast improvement
- Background cleanup
- Object cleanup
- Edge refinement
- Detail restoration
- Cropping
- Recomposition
- Image expansion
- Background replacement
- Subject isolation
- Style refinement
- Brand alignment

Preserve the original subject and intended meaning unless
the task specifically requests a creative transformation.

The goal is:

```
EXISTING ASSET
      ↓
INSPECT
      ↓
CAN IT BE IMPROVED?
      ↓
YES → ENHANCE
      ↓
NO → RETAIN OR REPLACE
      ↓
VISUAL QA
```


==================================================
4. IMAGE-TO-IMAGE IMPROVEMENT
==================================================

When an existing image is useful but visually weak:

Use it as a reference rather than starting from zero.

Preserve:

- Subject identity
- Product identity
- Architecture
- Composition where appropriate
- Important branding
- Required objects
- Relevant visual information

Improve:

- Detail
- Lighting
- Composition
- Realism
- Resolution
- Cleanliness
- Professional presentation


==================================================
5. VIDEO GENERATION
==================================================

When video is requested:

Use the highest-quality video-generation capability available.

The system should support:

- Text-to-video
- Image-to-video
- Reference-image video
- Video extension
- Scene continuation
- Cinematic camera movement
- Character movement
- Environmental movement
- Product animation
- UI/product demonstrations
- Background motion
- Short promotional sequences

Video prompts should define:

- Subject
- Environment
- Camera
- Lens/look
- Camera movement
- Subject movement
- Lighting
- Composition
- Duration
- Aspect ratio
- Mood
- Visual style
- Audio requirements when supported


==================================================
6. EXISTING VIDEO ENHANCEMENT
==================================================

If a project already contains video:

Inspect it before replacing it.

Determine whether it can be improved through:

- Upscaling
- Resolution improvement
- Stabilization
- Noise reduction
- Color correction
- Lighting correction
- Frame interpolation
- Cropping
- Reframing
- Background treatment
- Audio improvement
- Scene extension
- Image-to-video transformation
- Cinematic enhancement

Preserve useful existing footage whenever possible.


==================================================
7. VISUAL CONSISTENCY
==================================================

Every visual asset within the same project must be evaluated
against the existing visual identity.

Maintain consistency in:

- Characters
- Products
- Architecture
- Locations
- Colors
- Lighting
- Materials
- Photography
- Illustration style
- 3D style
- Typography
- Composition
- Animation
- Motion

If reference images exist, use them when supported.

Do not generate visually unrelated assets simply because
they individually look good.


==================================================
8. PROJECT VISUAL AUDIT
==================================================

When modifying an existing project, perform a visual audit.

Inspect:

- Homepage
- Landing pages
- Navigation
- Hero sections
- Cards
- Dashboards
- Profiles
- Forms
- Empty states
- Error states
- Loading states
- Modals
- Tables
- Mobile layouts
- Tablet layouts
- Desktop layouts

Identify:

- LOW QUALITY
- OUTDATED
- INCONSISTENT
- BROKEN
- MISSING
- DUPLICATED
- POORLY CROPPED
- LOW RESOLUTION
- UNNECESSARY
- PLACEHOLDER


==================================================
9. INTELLIGENT ASSET DECISION
==================================================

For every existing visual, choose one:

- **RETAIN**: Keep the existing asset because it already meets the standard.
- **ENHANCE**: Improve the existing asset while preserving its identity.
- **EDIT**: Modify specific portions of the asset.
- **RESTORE**: Repair damaged or degraded visual information.
- **UPSCALE**: Increase usable resolution.
- **ANIMATE**: Convert a static visual into motion where appropriate.
- **REPLACE**: Replace the asset when it cannot meet the required standard.
- **CREATE**: Generate a new asset when none exists.


==================================================
10. DO NOT DESTROY EXISTING WORK
==================================================

Never overwrite an existing production asset before:

1. Inspecting it.
2. Determining its purpose.
3. Creating an improved version.
4. Comparing the versions.
5. Verifying the improved version.
6. Confirming the application still references the correct asset.

Preserve originals whenever practical.


==================================================
11. VISUAL QUALITY CONTROL
==================================================

Every generated or enhanced visual must pass a visual QA process.

Check:

- [ ] Subject accuracy
- [ ] Composition
- [ ] Resolution
- [ ] Aspect ratio
- [ ] Lighting
- [ ] Color
- [ ] Detail
- [ ] Realism/style consistency
- [ ] Anatomy
- [ ] Object integrity
- [ ] Text integrity
- [ ] Branding
- [ ] Cropping
- [ ] Background
- [ ] Edge quality
- [ ] Artifacts
- [ ] Project consistency
- [ ] Responsive presentation

If the result fails materially:

REGENERATE or RE-EDIT or RE-ENHANCE

Do not mark the task complete simply because an asset was generated.


==================================================
12. BROWSER VISUAL QA
==================================================

After integrating an asset:

Open the application and inspect it in the browser.

Check:

- Desktop
- Tablet
- Mobile

Verify:

- Image rendering
- Video rendering
- Cropping
- Aspect ratio
- Loading behavior
- Performance
- Responsiveness
- Accessibility
- Placement
- Animation
- Interaction

The asset is not considered complete until it works correctly
inside the actual application.


==================================================
13. PERFORMANCE
==================================================

Visual quality must not unnecessarily destroy application performance.

Automatically consider:

- WebP
- AVIF
- Appropriate JPEG/PNG usage
- Responsive image sizes
- Lazy loading
- Video compression
- Poster images
- Responsive video
- CDN delivery
- Caching
- Asset preloading where appropriate

Use the highest practical quality for the intended display size.


==================================================
14. ACCESSIBILITY
==================================================

Every meaningful visual integrated into an application must
consider accessibility.

Provide where appropriate:

- Alt text
- Accessible labels
- Captions
- Transcripts
- Reduced-motion behavior
- Sufficient contrast
- Non-visual alternatives for important information

Do not communicate critical information exclusively through imagery
or animation.


==================================================
15. AI MODEL SELECTION
==================================================

Do not assume one model is optimal for every visual task.

Choose the appropriate available capability for:

- IMAGE CREATION
- IMAGE EDITING
- IMAGE ENHANCEMENT
- IMAGE UPSCALING
- VIDEO CREATION
- IMAGE-TO-VIDEO
- VIDEO ENHANCEMENT
- 3D CONTENT
- MOTION GRAPHICS

Use the highest-quality available model/capability when quality
is the priority.

Use faster/lower-cost generation when appropriate for iteration,
testing, thumbnails, or non-production drafts.


==================================================
16. PROMPT ENGINEERING
==================================================

Do not send vague visual prompts.

Construct detailed prompts containing, when relevant:

- SUBJECT
- ENVIRONMENT
- COMPOSITION
- CAMERA
- LIGHTING
- MATERIALS
- COLOR
- STYLE
- DEPTH
- PERSPECTIVE
- MOTION
- MOOD
- BRANDING
- REFERENCE INFORMATION
- OUTPUT FORMAT


==================================================

==================================================

For important visuals:

```
Draft
  ↓
Generate
  ↓
Inspect
  ↓
Identify defects
  ↓
Improve prompt/instructions
  ↓
Regenerate
  ↓
Compare

```


==================================================
18. EXISTING PROJECTS
==================================================

When entering an existing project:

DO NOT assume its current visuals are correct.

Perform a visual inventory.

Identify:

1. What exists
2. What is missing
3. What is low quality
4. What can be enhanced
5. What should remain
6. What should be replaced
7. What new visuals are required

Improve the project progressively rather than unnecessarily
rebuilding everything.


==================================================
19. UNIVERSAL DESIGN ADAPTATION
==================================================

Do not impose one visual style on every project.

First identify the project's:

- Brand
- Industry
- Audience
- Existing design language
- Product positioning
- Color system
- Typography
- UX patterns
- Visual tone

Then generate/enhance visuals that belong to THAT project.

The system provides the production-quality standard,
not a universal artistic style.


==================================================
20. FINAL VISUAL COMPLETION RULE
==================================================

A visual task is COMPLETE only when:

```
AI GENERATION/ENHANCEMENT
        +
VISUAL INSPECTION
        +
QUALITY CONTROL
        +
PROJECT CONSISTENCY
        +
APPLICATION INTEGRATION
        +
RESPONSIVE QA
        +
ACCESSIBILITY
        +
PERFORMANCE
```

have been verified.

Never report a visual task as complete merely because
the file exists.
