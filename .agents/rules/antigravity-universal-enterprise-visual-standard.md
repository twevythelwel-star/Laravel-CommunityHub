# ANTIGRAVITY UNIVERSAL ENTERPRISE VISUAL STANDARD

## 1. PURPOSE

This standard applies globally to every project developed, maintained, redesigned, upgraded, or enhanced through Antigravity.

It applies equally to:

* New projects
* Existing projects
* Websites
* Web applications
* Mobile applications
* SaaS platforms
* Enterprise systems
* Dashboards
* Portals
* Marketing sites
* Maps
* Data visualizations
* 3D experiences
* Interactive applications
* Projects containing existing media
* Projects containing low-quality or outdated media

The objective is to ensure that every project's visual assets, animations, 3D content, maps, imagery, and media conform to a professional **enterprise production standard**.

Do not impose a single artistic style on every project.

Instead:

PROJECT IDENTITY
+
INDUSTRY
+
AUDIENCE
+
BRAND
+
UX
+
ENTERPRISE QUALITY

must determine the final visual treatment.

# 2. UNIVERSAL VISUAL INSPECTION

Before creating, replacing, modifying, or deleting visual assets, inspect the existing project.

Identify:

* Images
* Photographs
* Illustrations
* Icons
* Logos
* Maps
* Charts
* Diagrams
* Infographics
* 3D models
* 3D scenes
* Animations
* Motion graphics
* Videos
* Backgrounds
* Hero media
* Avatars
* Product imagery
* School/building imagery
* UI screenshots
* Decorative assets
* Placeholders

Classify each asset:

RETAIN
ENHANCE
CLEAN
RESTORE
UPSCALE
EDIT
ANIMATE
CONVERT TO 3D
OPTIMIZE
REPLACE
CREATE

# 3. PREEXISTING IMAGE CLEANUP

Existing images must not automatically be replaced.

Inspect each image for:

* Low resolution
* Compression artifacts
* Noise
* Blur
* Poor cropping
* Incorrect aspect ratio
* Color imbalance
* Exposure problems
* Poor contrast
* Background distractions
* Unwanted objects
* Visual clutter
* Damaged areas
* Jagged edges
* Inconsistent lighting
* Inconsistent branding
* Outdated presentation

When possible, improve the existing asset.

Preferred workflow:

ORIGINAL
↓
INSPECT
↓
CLEAN
↓
RESTORE
↓
ENHANCE
↓
UPSCALE
↓
COMPARE WITH ORIGINAL
↓
QUALITY CHECK
↓
INTEGRATE

Preserve the original asset until the enhanced version has been verified.

Do not alter important factual information contained within an image merely to make it look better.

# 4. IMAGE QUALITY STANDARD

Images integrated into enterprise applications should have:

* Appropriate resolution
* Correct aspect ratio
* Clean composition
* Consistent visual treatment
* Appropriate contrast
* Appropriate color
* Professional lighting
* Clean edges
* Minimal artifacts
* Correct subject representation
* Consistent branding
* Appropriate cropping
* Responsive behavior

Images must look intentional rather than randomly inserted.

# 5. ENTERPRISE ANIMATION STANDARD

Animations must communicate purpose.

Use animation to improve:

* Navigation
* Feedback
* Orientation
* Information hierarchy
* Product understanding
* Storytelling
* Visual engagement
* State changes
* Transitions
* Data interpretation

Avoid animation that exists merely because it is technically possible.

Animations must be:

* Smooth
* Controlled
* Purposeful
* Responsive
* Performance-conscious
* Consistent
* Accessible

Avoid:

* Excessive bouncing
* Random movement
* Excessive parallax
* Distracting looping
* Unnecessary motion
* Excessive particle effects
* Long blocking animations
* Animation that interferes with interaction

# 6. MOTION DESIGN SYSTEM

Every project using animation should establish consistent motion behavior.

Define:

* Entrance animation
* Exit animation
* Hover behavior
* Focus behavior
* Loading behavior
* Modal transitions
* Page transitions
* Scroll interactions
* Micro-interactions
* Data transitions
* Error/success feedback
* Mobile behavior

Animations should have consistent timing, easing, distance, and hierarchy.

Major interactions should receive more visual emphasis than minor interactions.

# 7. ACCESSIBLE MOTION

Support:

* prefers-reduced-motion
* Keyboard navigation
* Focus visibility
* Screen-reader-compatible states
* Non-motion alternatives

If motion is reduced, the application must remain fully usable.

Do not make critical functionality dependent on animation.

# 8. 3D VISUAL STANDARD

3D assets must be treated as enterprise production assets.

Inspect:

* Geometry
* Topology
* Materials
* Textures
* Lighting
* Shadows
* Reflections
* Scale
* Camera
* Perspective
* Polygon count
* File size
* Loading performance
* Mobile performance

3D content should be:

* Clean
* Realistic or intentionally stylized
* Properly scaled
* Professionally lit
* Consistent with the project
* Optimized for the target device

# 9. 3D PERFORMANCE

Never sacrifice application usability for unnecessary 3D complexity.

Use:

* Appropriate polygon counts
* Level of detail
* Compressed textures
* Efficient materials
* Lazy loading
* Progressive loading
* Appropriate asset formats
* GPU-conscious effects
* Mobile fallbacks

If a 3D model does not materially improve the experience, consider a high-quality 2D alternative.

# 10. 3D INTERACTION

Where appropriate, provide:

* Rotate
* Zoom
* Pan
* Hover
* Selection
* Highlighting
* Exploded views
* Layer visibility
* Contextual information

Interactions must remain intuitive.

Do not make users fight the camera.

# 11. MAP STANDARD

Maps require special handling.

Maps must prioritize:

* Geographic accuracy
* Legibility
* Consistent labeling
* Clear hierarchy
* Appropriate zoom levels
* Responsive behavior
* Accessibility
* Performance
* Accurate boundaries
* Accurate markers
* Appropriate attribution/licensing where required

Never distort geographic information simply for visual appearance.

Decorative map styling must not compromise geographic meaning.

# 12. INTERACTIVE MAPS

Interactive maps should support appropriate:

* Zoom
* Pan
* Search
* Location selection
* Marker interaction
* Clustering
* Filtering
* Layer control
* Directions
* Contextual information

Markers should remain visually distinguishable.

Avoid excessive marker clutter.

Use clustering or progressive disclosure when many locations exist.

# 13. MAP VISUAL HIERARCHY

Maps should visually distinguish:

PRIMARY INFORMATION
SECONDARY INFORMATION
REFERENCE INFORMATION

For example:

Primary:

* Selected location
* User location
* Important destination

Secondary:

* Nearby locations
* Categories
* Supporting landmarks

Reference:

* Roads
* Geographic boundaries
* Background terrain

Do not allow decorative styling to overwhelm the actual map information.

# 14. MAP DATA INTEGRITY

Never fabricate geographic coordinates, boundaries, locations, roads, or other factual geographic information.

If map data is incomplete:

* Identify the limitation
* Preserve uncertainty
* Do not invent precision
* Use the authoritative data source where available

Visual enhancement must never change factual geographic meaning.

# 15. DIAGRAMS AND DATA VISUALIZATION

Charts, diagrams, graphs, timelines, organizational structures, workflows, and infographics must prioritize:

* Accuracy
* Readability
* Hierarchy
* Accessibility
* Consistency
* Responsive behavior

Never sacrifice data accuracy for aesthetics.

Visual effects must not obscure data.

# 16. ICONS AND UI GRAPHICS

Icons must follow a coherent system.

Maintain consistency in:

* Stroke weight
* Geometry
* Corner radius
* Perspective
* Size
* Optical alignment
* Visual weight

Do not mix unrelated icon styles without a deliberate design reason.

# 17. ENTERPRISE VISUAL LANGUAGE

Every project should appear:

* Professional
* Intentional
* Consistent
* Trustworthy
* Refined
* Stable
* Accessible
* Scalable
* Production-ready

Avoid visual characteristics that make enterprise applications appear unfinished:

* Random gradients
* Generic AI imagery
* Excessive glassmorphism
* Inconsistent shadows
* Random border radii
* Excessive glow
* Uncontrolled animations
* Inconsistent icons
* Poor image cropping
* Placeholder imagery
* Excessive decorative effects
* Inconsistent spacing

# 18. BRAND CONFORMANCE

Before modifying visuals, identify the project's:

* Logo
* Brand colors
* Typography
* Design tokens
* Icon system
* Photography style
* Illustration style
* Motion language
* 3D language
* Component system

New or enhanced visuals must conform to these standards.

Do not overwrite established branding without explicit direction.

# 19. VISUAL CONSISTENCY

All visual assets should appear to belong to the same product.

Check consistency across:

* Images
* Illustrations
* Icons
* Maps
* 3D
* Animation
* Video
* Charts
* Backgrounds
* Cards
* Hero sections

A visually excellent individual asset is still unacceptable if it looks unrelated to the rest of the application.

# 20. RESPONSIVE VISUAL DESIGN

Every visual must be tested at:

* Mobile
* Tablet
* Laptop
* Desktop
* Large desktop

Verify:

* Cropping
* Scaling
* Position
* Text overlap
* Animation behavior
* Map controls
* 3D interaction
* Video dimensions
* Loading behavior

Do not simply scale desktop visuals down to mobile.

# 21. PERFORMANCE STANDARD

Visual quality must coexist with performance.

Optimize:

* Images
* Videos
* 3D models
* Textures
* Animations
* Maps
* Fonts
* Icons

Use:

* Responsive images
* Modern image formats
* Lazy loading
* Proper caching
* CDN delivery where appropriate
* Video posters
* Progressive loading
* Asset compression
* Code splitting
* 3D lazy loading

Do not load large visual assets before they are needed.

# 22. VISUAL LOADING EXPERIENCE

Large visual assets must have appropriate loading states.

Use:

* Skeletons
* Blur placeholders
* Progressive image loading
* Video poster frames
* Lightweight fallback visuals
* 3D loading indicators

Avoid blank screens caused by heavy visual assets.

# 23. IMAGE AND VIDEO GENERATION

When new media is required, use the highest-quality available AI generation capability appropriate to the task.

Support:

* Text-to-image
* Image-to-image
* Image enhancement
* Image restoration
* Image upscaling
* Text-to-video
* Image-to-video
* Reference-based generation
* Video enhancement
* Video extension

Do not use a lower-quality placeholder when production-quality generation is available.

# 24. INTELLIGENT EXISTING-ASSET IMPROVEMENT

For every existing visual, ask:

Can this asset be improved without losing its identity or factual meaning?

If YES:

ENHANCE IT.

If NO:

RETAIN IT OR REPLACE IT BASED ON PROJECT REQUIREMENTS.

Never replace an existing asset simply because AI can generate another one.

# 25. VISUAL VERSION CONTROL

When modifying important assets:

Original
↓
Candidate Enhancement
↓
Review
↓
Approved Version

Keep the original available until the new version is confirmed.

Avoid irreversible destructive edits.

# 27. BROWSER VALIDATION

After visual implementation:

1. Launch the application.
2. Inspect the actual rendered result.
3. Test desktop.
4. Test tablet.
5. Test mobile.
6. Interact with animations.
7. Interact with maps.
8. Interact with 3D.
9. Test video.
10. Inspect loading behavior.
11. Inspect accessibility.
12. Inspect performance.

Do not approve visuals based solely on the source files.

# 30. ENTERPRISE COMPLETION RULE

Visual work is COMPLETE only when:

VISUAL QUALITY
+
BRAND CONFORMANCE
+
UX
+
ACCESSIBILITY
+
RESPONSIVENESS
+
PERFORMANCE
+
DATA INTEGRITY
+
SECURITY WHERE RELEVANT
+
BROWSER VALIDATION

have been checked.

A generated file existing in the project does NOT mean the visual task is complete.

The final question is:

"Does this visual improve the actual production application while conforming to its enterprise standards?"

If the answer is no, continue improving it.
